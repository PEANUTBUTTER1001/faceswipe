# Android Settings 디자인 지침

**관련 설정을 사용자 목적별로 묶고, 행에서 현재 상태와 다음 동작을 즉시 읽을 수 있는 Android 앱 설정 화면.** 사용자가 기존 QRon의 화면 구성과 조작 방식에 가까운 결과를 원할 때 우선 선택. 시각 기본값은 하나의 배경, 섹션 소제목, 일정한 행 정렬로 이루어진 단일 열 목록.

Android 공식 가이드는 관련 설정의 그룹화, 필요에 따른 하위 화면, 설정 유형에 맞는 선택 방식, 시스템 설정 존중을 권장. 아래 수치와 화면 예시는 이 프로젝트에서 재현 가능한 **설계 시작값**. 기존 제품에 적용할 때는 현재 디자인 토큰과 실제 콘텐츠를 우선. [Android Settings 가이드](https://developer.android.com/design/ui/mobile/guides/patterns/settings) · [Android 설정 그룹화](https://developer.android.com/develop/ui/views/components/settings/organize-your-settings) · [프로젝트 디자인 지침](../디자인프롬프트v2.md)

## 1. 설계 입력

| 항목 | 필요한 내용 | 정보가 부족할 때 |
|---|---|---|
| 사용자와 진입점 | 누가 어떤 상황에서 설정을 열며 어디에서 들어오는가 | 제공된 탐색 구조를 기준으로 설계하고, 새 진입점은 제안으로 표시 |
| 설정 인벤토리 | 이름, 목적, 유형, 기본값, 현재 값, 영향 범위, 사용자 행동 | 제품 문서와 구현에서 확인한 항목만 사용. 확정되지 않은 기본값은 명시 |
| 상태와 권한 | 저장 실패 가능성, 시스템 권한, 기능·기기 지원 여부, 관리자 제한 | 알려진 의존 조건만 설계하고 나머지는 확인 항목으로 남김 |
| 화면과 토큰 | 지원 Android 버전, 화면 크기, 글꼴, 색상, 라이트·다크, 언어 | 기존 앱 토큰 재사용. 신규 앱이면 역할별 색과 크기 시작값 제안 |
| 출력 형식 | 시안, 상세 명세, 인터랙티브 프로토타입, Compose 구현 중 필요한 것 | 화면·상태 명세와 검수 항목 제시. 구현 요청 시 기존 모듈과 API 확인 |

## 2. 화면 구성

1. **화면 제목과 진입점.** 기존 앱의 상단 바 또는 고정 제목 영역에 ‘설정’을 표시. 하위 화면이면 뒤로 가기 제공. 개인정보 안내처럼 화면 전체에 적용되는 짧은 설명은 제목 아래 한 번 표시.
2. **설정의 그룹화.** 사용자가 함께 찾는 항목을 묶고, 짧은 명사형 소제목 부여. 기본값은 한 화면에서 탐색 가능하도록 구성. 하위 항목이 많거나 조건·설명이 독립적인 경우 해당 섹션을 상세 화면으로 분리. 루트 행에는 상세 화면에서 바뀌는 현재 값이나 상태 요약 표시.
3. **배치 순서.** 주요 기능의 환경설정, 데이터·개인정보, 화면, 앱 정보 순을 출발점으로 삼고 제품의 사용 빈도와 위험도를 반영. 데이터 삭제는 관련 데이터 섹션 끝에 배치. 자주 쓰는 실행 기능은 해당 작업 화면에서 발견 가능하게 설계.
4. **목록 표면.** 같은 배경 위에 행을 나열하고 소제목과 여백으로 그룹 경계 형성. 그룹 안은 일정한 간격으로 연결하고, 행 구분이 어려울 때만 텍스트 시작선에 맞춘 구분선 사용. 아이콘은 기능 구별 또는 상태 전달에 필요한 경우 사용.
5. **화면 폭과 스크롤.** 휴대전화에서는 단일 열 본문 스크롤. 앱 공통 하단 바가 있으면 안전 영역과 바 높이를 본문 끝에 반영. 넓은 화면에서는 기존 앱의 본문 폭 규칙을 우선 적용. 여러 하위 화면을 오가는 정보 구조에는 목록·상세 분할을 검토. [Android Settings 가이드](https://developer.android.com/design/ui/mobile/guides/patterns/settings)

## 3. 항목별 UI 계약

| 항목 | 표시 | 탭 동작과 상태 |
|---|---|---|
| 즉시 변경되는 이진 설정 | 왼쪽 제목·보조 설명, 오른쪽 스위치 | 행 전체에서 한 번 전환. 접근성 역할과 현재 상태를 하나의 대상으로 노출 |
| 단일 선택 | 제목과 현재 값. 선택지 차이가 있으면 설명 제공 | 일반적으로 행을 눌러 라디오 선택 대화상자 또는 하위 화면 열기. 짧고 의미가 자명한 소수 선택지는 제품의 분할 선택 컨트롤 검토 |
| 권한·시스템 기능 | 권한명, 현재 상태, 사용에 필요한 설명 | 행에서 필요한 이유나 설정 경로 안내. 복귀 시 OS 상태 재조회. 사용 불가와 꺼짐을 문구로 구별 |
| 여러 선택 | 목적을 알려주는 제목, 필요 시 현재 개수 | 서로 독립적인 선택에는 체크박스 사용. 저장 또는 적용 시점이 있는 경우 버튼과 문구로 명시 |
| 세부 설정 | 제목, 필요 시 요약값과 이동 화살표 | 화면 전환. 뒤로 돌아올 때 기존 목록 위치와 변경된 값 확인 가능 |
| 읽기 전용 정보 | 제목과 끝쪽 값 | 버전·빌드 번호 등은 일반 텍스트 행. 복사가 필요하면 접근 가능한 별도 동작 명시 |
| 데이터 삭제 | 대상이 드러나는 행동 문구, 필요 시 범위·건수 | 영향이 크면 확인과 취소 제공. 실행 중 재탭 방지. 완료·실패 표시 및 지원하는 경우 실행 취소 |

이진 선택과 하나의 값을 고르는 선택은 의미가 다르므로 라벨과 조작 방식도 구분. 설정은 값을 제어하고, 화면 이동 행은 이동 결과를 예측할 수 있게 표현. [Android Settings 가이드](https://developer.android.com/design/ui/mobile/guides/patterns/settings)

## 4. 시각 규격과 접근성

| 속성 | 기본안 | 검증 및 조정 |
|---|---|---|
| 좌우 인셋 | 16–24dp, QRon 기준 20dp | 제목·소제목·행의 텍스트 시작선 일치. RTL에서는 start/end 사용 |
| 행 크기 | 최소 높이 56–64dp, QRon 기준 60dp | 보조 설명·확대 텍스트에 따라 높이 증가. 독립 조작 영역은 최소 48×48dp |
| 섹션 간격 | 그룹 전 20–24dp, 소제목 아래 4–8dp | 그룹 내부 간격보다 그룹 사이 간격을 크게 유지 |
| 글자 위계 | 제목 24sp, 행 제목 15–16sp, 설명 13–14sp, 소제목 12sp부터 검토 | 제품 타이포그래피 토큰 재사용. 줄바꿈 허용, 설명·상태의 대비 확인 |
| 색 | 배경, 기본 텍스트, 보조 텍스트, 브랜드, 성공, 위험을 의미별 토큰으로 지정 | 색에 더해 상태 문구·스위치·선택 표시 제공. 라이트·다크에서 각각 확인 |
| 상태 피드백 | 탭 피드백과 기본 전환 동작 사용 | 대기·저장 실패는 해당 행 주변에 표시. 화면 전체가 영향을 받는 경우에만 공통 오류 사용 |

48dp는 Android 접근성 권장 기준. 위의 나머지 수치는 제품용 기본안. Android 14 이상에서는 최대 200% 글꼴에서 텍스트·행·안전 영역을 확인. TalkBack이 제목, 행 이름, 역할, 현재 상태를 예측 가능한 순서로 읽는지 직접 확인. [Compose 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults) · [Android 14 글꼴 확대](https://developer.android.com/about/versions/14/features#non-linear-font-scaling)

## 5. 구현과 예외 상태

- **Compose 구조.** 화면 제목과 목록을 분리하고, 기존 앱 셸의 내비게이션을 사용. 고정된 소수 설정은 스크롤 가능한 `Column`, 동적이거나 긴 목록은 `LazyColumn`과 안정 키 사용. 제목에는 heading 의미 부여. 스위치 행은 한 곳에서 토글을 처리하고, 탐색 행·읽기 전용 행은 역할을 구별.
- **상태 공급.** 화면 상태는 기존 ViewModel·설정 저장소에서 전달. 행은 현재 상태를 표시하고 사용자 입력을 콜백으로 전달. 즉시 적용 옵션은 변경 즉시 표시. 비동기 저장이 실패하면 실제 저장된 값으로 복구하고 재시도 방법 제공.
- **권한 상태.** 앱 환경설정과 시스템 권한을 각자의 상태 원천에서 읽음. 권한이 거부되거나 기기에서 기능이 지원되지 않으면 해당 행의 설명과 가능한 다음 행동을 구체화.
- **텍스트와 상호작용.** 길어진 값은 설명 아래 줄로 옮기거나 하위 화면에 전체 값 제공. 외부 설정에서 돌아오기, 스크롤 중 테마 전환, 읽기 전용 행, 마지막 행 접근을 각각 확인. [Compose 접근성 기본값](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)

### QRon 적용 예시

| 섹션 | 항목 | 표현 |
|---|---|---|
| 스캔 | 인식할 때 진동, 인식할 때 소리 | 두 스위치 행 |
| 화면 스캔 | 접근성 권한, 빠른 설정 타일, 사용 방법 | 현재 상태와 이동 또는 안내 |
| 기록 | 기록 저장, 같은 코드 합치기, 기록 전체 삭제 | 스위치·설명·삭제 확인 |
| 화면 | 시스템·라이트·다크 | 짧은 3분할 선택 컨트롤 |
| 정보 | 개인정보 처리방침, 라이선스, 버전 | 안내 시트 또는 상세 화면, 버전은 읽기 전용 |

예시의 항목과 배치는 QRon의 기존 구성에서 가져온 것. 다른 앱에는 그 앱에서 사용자가 찾는 설정만 적용. [QRon 설정 화면](../feature/settings/src/main/java/com/peanutbutter1001/qron/feature/settings/SettingsScreen.kt)

## 6. 바로 쓰는 디자인 요청문

아래 문단의 대괄호를 실제 값으로 바꿔 요청에 사용.

> [앱 이름과 핵심 작업]의 Android 설정 화면을 디자인해줘. 사용자와 진입점은 [대상·경로], 설정 목록과 기본값은 [항목·기본값·권한·지원 조건], 제품의 기존 디자인 기준은 [색·타이포·내비게이션 또는 참고 화면], 원하는 결과물은 [시안·프로토타입·Compose 구현]이야.
>
> Android Settings 패턴에 맞춰 사용자가 함께 찾는 설정을 묶고, 한 화면에서 이해할 수 있는 기본 옵션을 우선 배치해. 배경 한 장 위에 단일 열로 구성하고 소제목·여백·공통 시작선으로 섹션을 구분해. 행 제목과 설명은 시작 쪽, 스위치·현재 값·이동 화살표는 끝쪽에 정렬해. 상태를 직접 바꾸는 행, 상세 화면으로 이동하는 행, 읽기 전용 행, 데이터 삭제 행을 서로 구별해.
>
> 각 설정의 기본·활성·비활성·권한 부족·저장 실패 상태를 실제 문구로 보여줘. 시스템 권한 화면에서 복귀하면 상태를 다시 읽고, 삭제는 대상과 범위를 확인할 수 있게 해. 좁은 화면, 라이트·다크, 최대 글꼴 확대와 TalkBack에서 같은 순서와 동작이 유지되도록 설계해. 결과에 화면 구조, 행별 동작, 디자인 토큰, 상태별 시안, 구현 전달 사항과 검수 기준을 포함해. 확인되지 않은 기능과 값은 가정으로 표시해.

## 7. 출시 전 검수

| 판정 | 통과 기준 |
|---|---|
| 필수 · 탐색 | 대표 사용자 과제를 정하고, 사용자가 섹션 이름과 행 제목만 읽어 첫 시도에 올바른 설정을 찾는지 관찰 |
| 필수 · 상태 | 켜짐·꺼짐·사용 불가·권한 거부·실패에서 표시값과 실제 상태 일치. 재진입 후 저장값 확인 |
| 필수 · 위험 행동 | 삭제 대상과 범위가 분명하고 취소 시 데이터 유지. 중복 실행 방지와 실제 복구 지원 범위 확인 |
| 필수 · 접근성 | 48dp 터치 영역, 좁은 폭·최대 글꼴에서 가림 여부, TalkBack 읽기 순서와 한 번의 탭에 한 번만 실행되는지 확인 |
| 권장 · 시각 일관성 | 라이트·다크와 지원 언어에서 제목·행 시작선, 색의 역할, 가장 긴 문구, 마지막 행의 하단 여백 확인 |
| 권장 · 제품 검증 | 대표 사용자에게 설정 찾기, 값 변경, 권한 복귀, 실수 취소 과제를 주고 혼동 지점을 다음 시안에 반영 |

출시 품질 판정에는 실제 화면의 동작과 지원 환경에서 확인한 결과를 사용. 시안 검토에서는 검증할 항목과 기대 결과를 기록.
